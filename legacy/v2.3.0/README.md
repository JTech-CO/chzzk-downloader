# Chzzk Downloader

네이버 치지직의 VOD와 클립을 재인코딩 없이 MP4로 저장하는 Chrome 확장 프로그램입니다. 현재 버전은 **2.3.0**입니다.

## 2.3.0 변경 사항

- **대용량 MP4 전송 개선**: 먼저 요청한 구간이 느려도 다른 구간을 계속 받아 OPFS의 해당 위치에 바로 기록합니다. 256 MiB 이상, Range를 지원하는 파일에 16 MiB 분할을 적용합니다.
- **요청 부하 조절**: 확장프로그램의 전송 엔진이 전체 요청을 최대 8개로 관리합니다. 호스트당 4개로 시작해 응답 속도와 오류에 따라 조절하며, 워커 전송 작업은 최대 2개를 실행합니다. Chrome에 위임한 일반 다운로드는 이 요청 예산에서 제외됩니다.
- **실패·중지 후 복구**: 작업 목록을 브라우저에 저장합니다. 파일 식별자와 크기가 유지된 대용량 직접 MP4는 받은 구간에서 이어받을 수 있습니다. 완성 파일의 최종 저장만 실패했다면 다시 받지 않고 저장을 재시도합니다.
- **디스크로 스트리밍**: HLS/DASH는 짧은 영상도 디스크에 순서대로 기록합니다. 전체 파일을 메모리에 모으지 않습니다. 기존 HLS/fMP4 재생 시간·탐색 정보 보정은 유지했습니다.
- **빠르게 표시되는 목록**: 첫 24개부터 표시하고 스크롤 또는 버튼으로 추가합니다. VOD는 세로 목록, 클립은 2열 카드로 표시하며 화면 근처의 항목만 DOM에 유지합니다.
- **다운로드 전용 화면**: 진행률, 전송량, 속도, 남은 시간, 중지·이어받기·파일 보기 기능을 제공합니다. Chrome의 실제 저장 완료를 확인한 뒤 완료로 표시합니다.
- **접근성과 작은 창 대응**: 키보드 탭 전환, Escape 닫기, 포커스 표시, 유연한 패널 크기를 적용했습니다. 제목에 따옴표가 있어도 원문을 안전하게 전달합니다.

병렬 연결은 회선이나 CDN의 속도 제한을 없애지 않습니다. 개선율은 영상·CDN·회선·디스크에 따라 달라지며, 이번 릴리스에 대한 실제 CDN 전후 속도 비교 수치는 아직 없습니다.

## 설치와 사용

**지원 환경**: Chrome 116 이상. Whale 등 다른 Chromium 브라우저는 같은 확장프로그램·OPFS API 지원이 필요하며 별도 실기 검증은 하지 않았습니다.

1. `chzzk-downloader.zip`을 풀고 `chrome://extensions`에서 개발자 모드를 켭니다.
2. **압축 해제된 확장 프로그램을 로드합니다**로 폴더를 선택합니다.
3. 기존 설치를 업데이트할 때는 진행 중인 다운로드를 먼저 마치거나 중지하고, 기존 경로에 파일을 갱신한 뒤 확장프로그램의 **새로고침**을 누릅니다. 작업 기록 보존을 위해 제거 후 재설치하는 방식은 피합니다.
4. 치지직 페이지를 새로고침하고 채널의 **동영상** 또는 **클립** 탭에서 오른쪽 아래 다운로드 버튼을 누릅니다.
5. 영상을 선택하고 **다운로드** 탭에서 상태를 확인합니다.

검색과 최신순·과거순·인기순 정렬은 **현재 불러온 목록**에 적용됩니다. 채널 전체를 대상으로 찾으려면 **전체 불러오기**를 먼저 사용합니다. 패널을 닫으면 전체 불러오기는 중지되며 다운로드 작업은 계속됩니다.

## 저장과 복구

| 방식 | 처리 | 중지 후 재시도 |
|---|---|---|
| 256 MiB 이상 직접 MP4 + Range 지원 | 병렬 Range → OPFS 임의 위치 기록 → Chrome 저장 | 같은 URL 경로·크기·ETag/Last-Modified가 확인되면 받은 구간 재사용 |
| 작은 MP4 또는 Range 미지원 | Chrome Downloads에 위임 | Chrome이 지원하면 이어받기, 아니면 다시 받기 |
| HLS/fMP4 · 지원되는 DASH | 조각 병렬 전송 → 디스크 순차 기록 → Chrome 저장 | 미완성 전송은 처음부터 재시작 |
| 이미 완성된 임시 파일 | Chrome 저장 재시도 | 영상 재전송 없이 다시 저장 |

브라우저 종료나 확장프로그램 업데이트는 실행 중인 작업을 중단할 수 있습니다. 브라우저를 다시 열면 기록을 복원하고, 이어받기가 가능한지 파일 정보를 확인합니다. 완료한 Range는 디스크 반영 뒤 최대 8개 구간마다 체크포인트를 기록하므로 갑작스러운 종료에서는 마지막 일부 구간을 다시 받을 수 있습니다.

중지된 작업의 임시 파일은 이어받기를 위해 남을 수 있습니다. **목록에서 지우기**는 작업 기록과 해당 임시 데이터를 정리하며 이미 다운로드 폴더에 저장한 파일은 삭제하지 않습니다. 최종 저장 중에는 임시 파일과 저장본이 함께 존재할 수 있으므로 여유 디스크 공간이 필요합니다.

요청 응답/본문 수신이 30초 동안 멈추면 실패를 감지하고, 일시 오류에는 Retry-After와 지수 백오프를 적용해 최대 4회 시도합니다. HLS/DASH의 정렬 대기 버퍼 목표는 64 MiB이며, 수신 중인 조각과 MP4 메타데이터 메모리는 별도입니다.

## 지원 범위

- 직접 MP4는 원본 바이트를 그대로 저장하며, HLS는 fMP4 초기화 조각이 있는 스트림을 처리합니다.
- DASH는 직접 파일 주소 및 제한된 SegmentTemplate/SegmentTimeline을 지원합니다. Number, Time, Bandwidth, 상대 BaseURL을 해석합니다.
- 암호화·보호된 스트림, 별도 오디오 병합이 필요한 스트림, 여러 Period의 DASH, SegmentList, 불연속·누락 구간의 HLS는 지원 오류로 안내합니다. 모든 재생 형식을 지원하는 범용 변환기는 아닙니다.
- 로그인이 필요한 콘텐츠는 사용자의 치지직 로그인과 시청 권한이 필요합니다. 비공식 API가 변경되면 동작에 영향을 받을 수 있습니다.
- 다운로드 UI는 채널의 `videos`·`clips` 페이지에만 표시됩니다.

## 개발과 검증

| 파일 | 역할 |
|---|---|
| `content.js`, `content.css` | 점진적 목록, 가상화, 다운로드 상태 UI |
| `media-resolver.js`, `dash-parser.js` | 치지직 재생 정보와 DASH 다운로드 계획 |
| `background.js` | 작업 기록, Chrome Downloads, 실행부 연결 |
| `offscreen.js`, `offscreen.html` | 전용 워커와 완성 파일의 Blob URL 유지 |
| `download-engine.js` | 요청, 타임아웃, OPFS 기록, 체크포인트 |
| `download-core.js`, `media-plan.js` | 요청 스케줄러·IndexedDB·입력/응답 검증 |
| `mp4.js` | 기존 fMP4 재생 메타데이터 보정 |

Node.js 20 이상에서:

```powershell
npm install
npx playwright install chromium
npm test
powershell -ExecutionPolicy Bypass -File .\package.ps1
```

브라우저 테스트는 별도 임시 프로필과 로컬 HTTPS 서버를 사용합니다. 실제 사용자 프로필·다운로드 기록·치지직 계정을 사용하지 않습니다. UI 스크린샷은 `test-results/`에 생성합니다. 이 테스트는 CDN 속도나 실제 플레이어의 영상 재생 품질을 측정하지 않습니다.

배포 스크립트는 실행에 필요한 15개 파일만 ZIP에 포함합니다. 테스트, 인증서, 레거시, 개발 의존성은 제외합니다.

이전 전체 보존본은 `legacy/v2.2.6/` 및 `legacy/v2.2.5/`에 있습니다. 2.2.6 스냅샷의 21개 파일은 변경 전 원본과 SHA-256 일치를 확인했습니다. 자세한 변경 내용은 [업데이트 안내](bug-report.md)를 참고하세요.

## 데이터 처리

모든 미디어 처리는 사용자의 브라우저와 치지직 공식 API·지정 CDN 사이에서 이루어집니다. 개발자 서버로 데이터나 이용 기록을 보내지 않습니다. 작업 제목·상태·진행률과 체크포인트는 로컬 IndexedDB, 임시 영상 데이터는 OPFS에 저장합니다. `downloads` 권한으로 확장프로그램이 시작한 다운로드 ID의 상태만 조회합니다.

사용하지 않는 `activeTab` 권한을 제거했으며 새 권한은 추가하지 않았습니다. [개인정보 처리방침](privacy-policy.html)을 참고하세요.
