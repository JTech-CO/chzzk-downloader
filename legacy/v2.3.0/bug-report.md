# Chzzk Downloader v2.3.0 업데이트 안내

2026년 9월 20일. v2.2.6의 전체 21개 파일을 `legacy/v2.2.6/`에 복사하고 SHA-256 일치를 확인한 뒤 작업했습니다. 기존 `legacy/v2.2.5/`도 유지합니다.

## 전송 속도와 안정성

2.2.6은 이미 16 MiB 구간을 최대 8개씩 받았습니다. 문제는 먼저 요청한 구간이 늦어지면 뒤쪽 요청도 멈추는 순차 기록 대기였습니다. 2.3.0은 전용 워커에서 OPFS SyncAccessHandle로 각 구간을 해당 바이트 위치에 기록해 이 대기를 제거했습니다. 요청한 범위·실제 수신 크기·전체 크기·파일 식별자 검증은 유지하고 강화했습니다.

요청 스케줄러를 전체 작업이 공유하며, 동시 요청 상한은 8개입니다. 호스트당 4개로 시작해 관측 속도와 오류에 따라 조절합니다. 429/5xx/연결 오류 시 동시성을 낮추고 재시도에는 Retry-After와 지수 백오프를 적용합니다. 헤더 응답 및 본문 수신에는 30초 정체 제한을 두었습니다. 브라우저에 위임한 일반 다운로드의 연결은 Chrome이 관리합니다.

HLS/DASH도 영상 길이에 관계없이 디스크로 스트리밍합니다. 작은 영상의 조각 전체를 RAM에 누적하던 경로를 없앴습니다. HLS의 순서 대기 버퍼 목표는 64 MiB이며 수신 중인 조각은 이 수치에 포함하지 않습니다. 직접 MP4의 원본 바이트와 기존 fMP4 재생 시간·타임라인·64비트 탐색 인덱스 보정은 유지했습니다.

## 작업 기록과 완료 처리

긴 전송은 offscreen 문서의 전용 워커가 수행하고 서비스워커는 Chrome 저장과 작업 기록을 담당합니다. 서비스워커 메모리에만 의존하던 작업 정보를 IndexedDB로 옮겼습니다.

- 대용량 직접 MP4는 디스크 기록을 반영한 뒤 체크포인트를 저장합니다. 다시 시작할 때 파일 경로·크기·검증자가 같으면 받은 구간을 재사용합니다.
- HLS/DASH의 미완성 전송은 처음부터 다시 받습니다. 이어받기가 가능한 것으로 표시하지 않습니다.
- `chrome.downloads.download`의 시작 콜백을 완료로 오인하지 않고, 실제 `complete` 상태를 확인합니다.
- 저장 실패를 오류로 알리며 완성된 임시 파일은 **다시 저장**할 수 있습니다.
- **목록에서 지우기**는 해당 작업 기록·임시 데이터만 정리합니다. 저장 완료된 사용자 파일은 유지합니다.
- 시작 직후 중지, HLS 중지, 동시 요청 실패 시 다른 요청 취소와 파일 정리를 처리합니다.

## 화면과 코드 구조

첫 페이지부터 목록을 표시하고 필요한 페이지를 추가로 불러옵니다. 검색·정렬의 대상이 현재 불러온 목록임을 표시합니다. VOD는 세로 목록, 클립은 2열 카드로 구성하고, 화면 가까운 항목만 DOM에 유지합니다. 진행률 변경 시 관련 항목만 갱신합니다.

다운로드 탭에 전송량·속도·남은 시간과 중지·다시 시도·파일 보기 기능을 모았습니다. 강한 CSS 초기화 규칙이 여백을 지우던 문제를 수정하고 작은 창, 키보드 조작, 포커스 표시를 보완했습니다. 영상 제목은 HTML 속성 문자열에 삽입하지 않습니다.

UI, 재생 정보 해석, 전송 엔진, MP4 보정, 브라우저 저장을 별도 파일로 나눴습니다. DASH의 Time/Bandwidth·상대 경로·반복 타임라인을 해석하고, 별도 오디오·보호된 콘텐츠 등 지원하지 않는 구조는 오류로 안내합니다. 사용하지 않는 `activeTab` 권한은 제거했습니다.

## 검증과 한계

**총 33개 자동 테스트가 통과했습니다**(Range 9개, 엔진·복구 회귀 17개, 브라우저 UI·DASH 6개, 실제 확장프로그램 통합 1개). JavaScript 15개 파일의 문법 검사도 통과했습니다.

자동 검증은 Range의 바이트 동일성, 앞 구간 정체 시 후속 요청 지속, 취소와 체크포인트 복원, 요청 수 제한, 재시도, 잘못된 미디어 계획, 저장 실패와 완료 상태를 다룹니다. 브라우저 UI 검증에는 2,400개 목록, 악의적인 HTML 형태의 제목, 키보드, 400px 폭과 작은 높이를 포함합니다.

격리된 Chromium에서 실제 확장프로그램을 로드해 로컬 HTTPS → 전용 워커 → OPFS → Chrome Downloads 저장을 확인했습니다. 일반 직접 다운로드, 파일명 보존, 임시 데이터 정리, 완료 기록의 브라우저 재시작 복원과 작업 기록 삭제 후 사용자 파일 보존도 검증합니다.

이 결과는 로컬 테스트 환경의 검증입니다. **실제 치지직 CDN의 전후 다운로드 속도, 10시간 이상 VOD 완주, macOS/Whale 및 여러 플레이어 재생은 이번 작업에서 새로 측정하지 않았습니다.** 속도 향상 배수나 모든 환경의 완주를 보장하지 않습니다. 릴리스 후 대표 VOD의 다운로드 시간·처리량·최종 저장 시간·최대 메모리를 같은 환경에서 비교할 필요가 있습니다.

지원 환경과 형식 제한, 개발 명령은 [README](README.md)에 정리했습니다.
